# 《Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection》解读

| 项目 | 内容 |
|---|---|
| 作者/机构 | Akari Asai 等，University of Washington + Meta |
| 发表 | arXiv:2310.11511（ICLR 2024） |
| 一句话总结 | 训练模型生成四类反思 token（Retrieve / IsRel / IsSup / IsUse），推理时自己决定"要不要检索、引用靠不靠谱"——把 RAG 的控制逻辑内化进模型 |

## 1. 研究背景与问题

- 传统 RAG 对每个问题都检索固定 top-k：简单问题被噪声干扰，难问题证据不够；引用错误无人把关。
- 问题：**能否让模型自适应地决定检索与自评？**

## 2. 核心方法

- 用 GPT-4 自动构造训练数据，微调模型在生成中插入特殊 token：
  - **Retrieve**：当前段落是否需要检索；
  - **IsRel**：检索内容是否相关；
  - **IsSup**：自己的陈述是否被检索内容支持；
  - **IsUse**：这段输出对回答问题是否有用。
- 推理时用 token 概率做树形决策（不同阈值 = 不同"反思程度"档位）。

## 3. 关键实验与结果

- 开放域 QA、推理、事实验证任务上超过 vanilla RAG 与无检索基线；显著减少无用引用。

## 4. 局限性与争议

- 需要专门训练；反思 token 的可靠性依赖数据质量。
- 与 Agentic RAG（模块 04 第 4 节）是"内化控制"vs"外部编排"的两条路线。

## 5. 与本知识库的关联

模块 04 高级范式表的核心一行；理解"拒答机制"如何通过 IsSup/IsUse token 落地。
