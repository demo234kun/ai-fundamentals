# 《Aspire: Can Models Self-Evolve from Vague Goals?》解读

| 项目 | 内容 |
|---|---|
| 作者/机构 | Self-Developing Agents 项目团队（三件套之一，2026.9） |
| 发表 | arXiv:2608.31111（2026-09-01） |
| 一句话总结 | 给 agent 一个模糊能力目标（"提升数学推理"）而不给具体任务，测它能否自己决定学什么、训出超过基座且**能被留存**的 checkpoint——30 个实验格只有 1 个通过留存阈值 |

## 1. 研究背景与问题

- 现有自动后训练基准（PostTrainBench、RSIBench-Data）都给了**明确的任务与评测**；真实场景里组织给的是模糊目标："把数学推理做好"。
- 论文形式化了一个缺失环节：**目标操作化（Target Operationalization）**——把宽泛意图翻译成可训练目标、学习信号与验证标准。
- 三问：RQ1 模糊目标 vs 显式任务差在哪？RQ2 能否自主产生**留存**的权重增益？RQ3 权重固定时 harness 能否自己进化？

## 2. 核心方法

- **两个进化面**：权重面（选数据/更新方法/超参/父 checkpoint）与 harness 面（改 runtime prompt/工具策略/工作流/记忆/验证流程）。
- **最小交互环境 + 信任边界**：只暴露语义动作（注册、训练/编辑、验证、评估、分叉、终止），隐藏后端；评测集密封。候选必须验证父代、登记数据、完整发布才能被评测——**agent 发明的、外来的、不完整的工件进不了计分谱系**。
- **留存原则**：晋级是显式的轮间操作，绝不在轮内自动替换。

## 3. 关键实验与结果

- RQ2 自适应反馈协议：30 个"配置×目标"格中 28 个产出 checkpoint，仅 2 个超过基座，**仅 1 个通过留存阈值**；best checkpoint 仍低于未进化基座（局部增益、全局退化）。
- RQ1：模糊目标让决策时间 +35 分钟/对、GPU 训练评估时间 −76 分钟/对；"读任务定义/查评测脚本"的痕迹密度 2.4~3.1 倍，LoRA 使用率 24.1%→89.8%——**在固定预算下，模糊目标改变的是搜索分布，不是目标质量**。
- RQ3：冻结权重时 agent 能造出可用的后继 harness，但最强的仍低于人工设计的 Qwen-Agent 参照。

## 4. 局限性与争议

- 作者自标的证据边界：RQ1 是 48 对匹配运行的描述性对比，非纯 prompt 隔离实验。
- 基座为 4B 级小模型，结论外推到前沿模型需谨慎。

## 5. 与本知识库的关联

模块 06 主线之①；与模块 01 的"后训练自动化"和模块 05 的"评测驱动迭代"直接接壤——Aspire 相当于给 PostTrainBench 加了一个"目标也得自己猜"的难度档。

## 6. 阅读建议

- 先读 §1 的三个 RQ 与 §3.3（交互环境与留存设计）——这套"密封评测 + 谱系审计"的工程设计是所有自进化实验该抄的作业。
- 数字记不住没关系，记住一句话：**跑完更新循环 ≠ 改进了目标能力；改进要以留存为准。**
