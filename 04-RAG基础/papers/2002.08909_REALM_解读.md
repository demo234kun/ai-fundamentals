# 《REALM: Retrieval-Augmented Language Model Pre-Training》解读

| 项目 | 内容 |
|---|---|
| 作者/机构 | Kelvin Guu 等，Google Research |
| 发表 | arXiv:2002.08909（ICML 2020） |
| 一句话总结 | 把检索器直接塞进预训练：模型在 MLM 预训练时就学会"有疑问先检索"，检索与生成联合优化——RAG 的"训练期"路线 |

## 1. 研究背景与问题

- RAG（同期工作）是在**预训练之后**接检索做微调。
- 问题：**如果从头预训练就带检索，模型能否把检索内化成本能？**

## 2. 核心方法

- 掩码 token 的预测概率 = 对检索文档的边缘化 `Σ_z p(z|[CLS]x)·p(y|x,z)`——检索器可微地参与预训练。
- **异步索引更新**：每几百步用最新编码器重建 Wikipedia 向量库（否则旧索引与编码器失配）。
- 检索器初始化：用 ICT（Inverse Cloze Task，"给答案猜问题所在句"）预训练。

## 3. 关键实验与结果

- 开放域 QA：NQ 上显著超过当时 SOTA；低资源场景优势更明显。

## 4. 局限性与争议

- 预训练成本极高（频繁重建索引）；异步更新带来训练不一致。
- 与 RAG 的路线之争：之后多数工作采用 RAG 的"预训练后接"路线（便宜、灵活）。

## 5. 与本知识库的关联

模块 04 第 1 节"向量化"之前的范式铺垫；理解"检索增强预训练 vs 检索增强生成"的分野。
