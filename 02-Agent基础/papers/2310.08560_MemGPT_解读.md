# 《MemGPT: Towards LLMs as Operating Systems》解读

| 项目 | 内容 |
|---|---|
| 作者/机构 | Charles Packer 等，UC Berkeley |
| 发表 | arXiv:2310.08560（2023.10，后发展为 Letta 公司） |
| 一句话总结 | 把 OS 的分层存储搬到 LLM：主上下文=内存，外部存储=磁盘，agent 用"函数调用"自己管理页面换入换出——在固定上下文窗口上模拟出无限记忆 |

## 1. 研究背景与问题

- 固定上下文窗口装不下长会话/大文档；朴素 RAG 一次检索又太粗糙。
- 问题：**能否让模型自己像 OS 管理虚拟内存一样管理自己的上下文？**

## 2. 核心方法

- **分层存储**：主上下文（system + working context）/ 召回存储（向量库）/ 归档存储（文件级）。
- **OS 原语**：`archival_memory_insert/search`、`recall_memory_search`、`core_memory_replace/append` 等函数——agent 通过 function call 主动分页。
- **中断机制**：上下文快满时触发 warning，agent 决定压缩哪些内容。
- **Flat vs Hierarchical**：Deep Memory Retrieval 证明简单扁平检索足以支撑多会话一致性。

## 3. 关键实验与结果

- 多会话一致性任务（跨 5 个 session 记住用户偏好）大幅超越固定上下文 + RAG 基线。

## 4. 局限性与争议

- 分页决策本身消耗 token 且会犯错；OS 类比在"注意力机制"层面并不严格。

## 5. 与本知识库的关联

模块 02 记忆小节；模块 05 compaction/状态管理设计的思想来源之一；Letta 是其后继开源项目。

## 6. 阅读建议

- 精读 §3（系统设计与函数表）和 §4.1（多会话实验）。
- 实践对照：Claude Code 的 compaction 与 MemGPT 的 agent 自主分页，体会"系统决策 vs 模型决策"的取舍。
