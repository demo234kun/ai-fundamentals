# 《Plan-and-Solve Prompting》解读

| 项目 | 内容 |
|---|---|
| 作者/机构 | Lei Wang 等，Sun Yat-sen University 等 |
| 发表 | arXiv:2305.04091（2023.5，ACL 2023 findings） |
| 一句话总结 | 发现 zero-shot CoT（"Let's think step by step"）在多步计算问题上仍会算错，提出"先出计划、再分步计算、最后验证"的 Plan-and-Solve 提示框架 |

## 1. 研究背景与问题

- Zero-shot CoT 提升了推理，但对**多步算术/逻辑**问题仍经常中途算错。
- 问题：**能否用提示结构强制模型"先规划后执行"？**

## 2. 核心方法

- 两个提示词：
  - **Plan 阶段**：` devise a plan and carry it out`——先生成整个解题计划（编号步骤）；
  - **Solve 阶段**：按计划逐步执行，每步输出计算过程；
  - 增强版 PS+：要求每步自提"这一步计算什么、表达式是什么"。
- 加入结果提取与验证指令。

## 3. 关键实验与结果

- GSM8K：zero-shot CoT 78.0% → Plan-and-Solve 80.8%；AQUA 等也稳定提升。
- 错误分析显示减少"步骤遗漏"和"中途计算错误"。

## 4. 局限性与争议

- 仍是 prompt 技巧，无训练；计划错了后面全错（缺少重规划机制——LangGraph 等框架补）。

## 5. 与本知识库的关联

模块 02 "Plan-and-Execute"范式的提示工程版本；理解 BabyAGI/LangChain Plan-and-Execute agent 的思想源头。
