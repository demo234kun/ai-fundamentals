# 《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》（RAG）解读

| 项目 | 内容 |
|---|---|
| 作者/机构 | Patrick Lewis 等，Facebook AI + UCL + NYU |
| 发表 | arXiv:2005.11401（NeurIPS 2020） |
| 一句话总结 | "RAG"一词的诞生：把生成模型接上可更新的非参数化记忆（Wikipedia 索引），知识一改就换库，不用重训模型，且可溯源 |

## 1. 研究背景与问题

- GPT-3 类模型知识截止、会幻觉、不可溯源；按领域微调每个知识任务又不现实。
- 问题：**如何把"记知识"与"用语言"解耦？**

## 2. 核心方法

- **RAG-Sequence**：一个检索文档决定整段生成（p(y|x)=Σ_z p(z|x)·p(y|x,z)）。
- **RAG-Token**：每个 token 可以基于不同检索文档生成（更细粒度，更贵）。
- 检索器：DPR 双塔（query/doc 分别编码），索引是 Wikipedia 密集向量库。
- 端到端训练：生成 loss 反向传播**穿过检索器**一起微调（也可用固定检索器）。

## 3. 关键实验与结果

- 开放域 QA（NQ/TriviaQA）：超过当时 SOTA（REALM、闭卷 BART）；事实核查任务接近 pipeline SOTA 且更省参数。

## 4. 局限性与争议

- 检索错则生成错（garbage in garbage out）；对"需要多篇综合"的问题能力弱。
